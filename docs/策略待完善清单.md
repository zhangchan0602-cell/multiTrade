# 当前策略体系待完善清单

> 适用范围：`short` 盘后版、`tail` 尾盘版、`rps90`、`leader`
>
> 整理日期：2026-05-21

## 1. 当前结论

当前策略体系已经具备日常出信号、历史归档、基础回测和部分结算能力，但整体仍处于“可运行、未完全研究闭环”的阶段。

从可继续投入优化的优先级看，建议排序如下：

1. `short` 盘后版
2. `rps90`
3. `tail` 尾盘版
4. `leader`

排序依据：

- `short` 盘后版因子结构最完整，且已有专门历史回放脚本，最适合继续迭代
- `rps90` 已有回测框架，但模型过于单一，优化空间明确
- `tail` 目前最大问题是数据口径偏弱，不宜只靠手调权重
- `leader` 目前更像候选池模型，尚未进入完整回测闭环

## 2. 各策略待完善项

### 2.1 `short` 盘后版

当前状态：

- 因子维度最完整，已覆盖启动、趋势、活跃、稳定、流动性五大类
- 权重与过滤阈值已配置化，便于调整
- 已有 `T+3` 历史回放脚本，可重算历史信号

主要问题：

- 动量类因子相关性偏高，存在重复表达同一段趋势的问题
- 过滤条件偏硬，部分交易日最终候选过少，信号供给不稳定
- 权重和阈值是固定值，未区分市场状态
- 目前更偏“横截面择股”，缺少市场环境过滤

建议优化：

1. 做因子去冗余测试，重点检查 `ret_3`、`ret_5`、`ret_10`、`ret_20`、`breakout_20`、`ma_alignment_20` 的边际贡献
2. 将部分硬过滤改成排序惩罚项，减少“当日只有 1-3 只票”的情况
3. 补充市场状态开关，例如趋势市、震荡市、退潮市使用不同参数组
4. 增加组合层约束，例如行业分散、题材拥挤度上限、单风格暴露限制
5. 将回测统计从均收益扩展到回撤、连续亏损、按月份分层、按市场阶段分层

### 2.2 `tail` 尾盘版

当前状态：

- 已独立配置权重和过滤阈值
- 会强调当日量能爆发和短期启动
- 已有历史归档，可接入统一回测框架

主要问题：

- 核心特征仍以日线 K 线为主，尾盘专属信息不足
- 历史样本偏少，且出现过硬过滤后样本很多、最终结果为 0 的情况
- 尾盘策略的入场口径并不是真实尾盘成交口径
- 当盘中快照缺失时，容易退化为日线近似逻辑，削弱策略意义

建议优化：

1. 优先补充分时数据，而不是先继续微调权重
2. 增加尾盘专属因子，例如 14:00 以后量能加速、14:30 后 VWAP 偏离、尾盘竞价强度、尾盘板块联动强度
3. 将尾盘回测改成基于真实尾盘近似成交价，而不是只用日线收盘或快照 close
4. 复核过滤阈值，重点排查 `pass_launch_window`、`pass_breakout_setup`、`pass_activity_setup` 是否叠加过严
5. 区分“盘中实时信号”和“降级日线参考信号”，不要混合评估

### 2.3 `rps90`

当前状态：

- 逻辑简单透明，容易解释和重算
- 已有专门回测脚本和统一回测入口
- 对中期趋势主线具备一定筛选能力

主要问题：

- 本质仍是单因子扩展模型，过度依赖趋势强度
- 容易扎堆到单一热点板块，风格暴露大
- 对回撤质量、波动结构、量价协同约束不足
- 容易在题材高位接力阶段失效

建议优化：

1. 在 `RPS20 + RPS90` 之外补充质量过滤，例如波动率、最大回撤、上影压力、成交额放大持续性
2. 增加行业拥挤度约束，避免同一主题集中持仓
3. 补充市场状态过滤，例如指数位置、连板情绪、主线强弱，用于决定是否开启策略
4. 回测时增加按主题、行业、月份、市场阶段的分层统计，识别失效环境
5. 评估是否保留“成交额加分”这一轻量排序项，或者替换为更稳定的质量指标

### 2.4 `leader`

当前状态：

- 模型思路清晰，强调行业龙头、抱团趋势、资金一致性
- 因子设计偏中期趋势风格，和短线模型形成区隔
- 已具备历史归档能力

主要问题：

- 当前更像“中期强势候选池”，不是成熟交易模型
- 硬过滤后样本仍很大，说明买点约束不足
- 尚未进入统一回测或独立回测框架
- 目前缺少持有周期、退出规则、成交口径验证

建议优化：

1. 先补历史回测，再讨论细化打分权重
2. 增加交易执行层过滤，例如回踩确认、趋势延续确认、放量不失真等
3. 为 `leader` 单独定义持有周期和退出规则，避免直接套用短线策略规则
4. 补充拥挤交易风险识别，例如高位爆量、连续大阳后衰减、单板块集中度过高
5. 将该策略定位明确为“候选池增强器”还是“独立实盘策略”，避免目标混乱

## 3. 回测体系待完善项

在下一阶段，历史回测应统一收敛到同一套规则，不再只依赖已有归档信号文件做被动回放，而是要基于 `Tushare` 历史数据，按历史交易日重新运行各策略、重新计算当日可买入标的，再按统一交易规则做持仓模拟。

## 3.0 统一历史回测目标规则

### 数据与信号生成

- 历史数据统一使用 `Tushare` 拉取
- 对每个历史交易日，重新运行对应策略，实时生成当日可买入股票，而不是只读取历史落盘结果
- 各策略都应接入这一套口径，包括 `short`、`tail`、`rps90`、`leader`

### 资金与仓位规则

- 单只股票预备金固定为 `10 万`
- 买入和卖出都按整百股执行
- 同时最多持有 `3` 只股票
- 当持仓已满 `3` 只时，当日新信号不能继续开仓，除非已有持仓先触发卖出

### 持有与卖出规则

- 个股买入后，不限制最长持有期限
- 止盈规则 1：当日涨停即卖出
- 止盈规则 2：若未涨停，则后续出现单日回撤 `5%` 即卖出
- 止损规则：股价跌破 `5 日线` 即卖出

### 回测实现要求

- 回测时需要记录每笔交易的理论买入日、买入价、买入股数、剩余现金、持仓天数、卖出触发原因
- `5 日线止损` 不能只看固定百分比，需要基于历史日线动态计算 `MA5`
- `涨停即出` 需要区分主板与创业板涨停阈值
- 回测结果至少要输出交易明细、资金曲线、持仓占用、胜率、平均收益、最大回撤

## 3.1 已具备的能力

- `short` 盘后版支持按历史交易日重算 Top5，并做 `T+3` 结算回放
- `rps90` 具备独立回测脚本
- 统一回测脚本已覆盖 `rps90`、`short`、`tail`
- 可输出单笔收益、胜率、出场原因、排名分层等基础统计

## 3.2 当前不足

1. `leader` 还没有真正纳入回测体系
2. 现有回测并未对所有策略做到“按历史交易日重跑策略并生成当日买点”
3. 当前回测还没有严格落实 `10 万单票预算 + 整百股 + 最多 3 仓` 的组合级约束
4. 当前止损规则多为固定比例，尚未统一切换到“跌破 5 日线止损”
5. 回测主要基于日线 `close`，不是成交级回测
6. 买入价、卖出价口径偏理想化，缺少 `open`、`VWAP`、尾盘真实成交近似
7. 没有手续费、滑点、冲击成本、成交量占比约束
8. 没有处理涨停买不到、跌停卖不掉、停牌、复牌跳空等执行约束
9. 没有滚动窗口 `walk-forward` 验证，参数稳定性不足
10. 横向对比样本不均衡，当前各策略历史沉淀长度不同，直接比较容易失真
11. 当前统计维度仍偏少，缺少组合回撤、收益曲线、月度收益、连续亏损段、信息比率等指标

## 3.3 建议补齐顺序

1. 先把四类策略统一接入“按历史日重跑策略”的回测框架，信号统一由 `Tushare` 历史数据重建
2. 在统一框架内落实 `10 万单票预算 + 整百股交易 + 最多 3 仓 + 无限持有 + 涨停止盈 + 单日回撤 5% 止盈 + 跌破 5 日线止损`
3. 再补真实或近似真实的入场/出场成交口径
4. 然后补交易成本和成交约束
5. 最后做滚动窗口参数验证和分市场状态评估

## 3.4 当前已落地入口

已新增统一组合回测入口：

```bash
npm run backtest:portfolio
```

或直接运行：

```bash
python3 scripts/strategy_backtest.py --portfolio --strategy all --lookback 30
```

当前入口已实现：

- 按历史交易日使用 `Tushare` 数据重跑策略信号
- 支持 `rps90`、`short`、`tail`、`leader`
- 单票 `10 万` 预算
- 整百股买入卖出
- 最多同时持有 `3` 只
- 不限制最长持有期限

- 未涨停时单日回撤 `5%` 即出

输出文件：

## 4. 数据层待完善项

## 4.1 当前已有数据

- `daily`：日线行情截面
- `daily_basic`：换手率、量比、市值等日指标
- `adj_factor`：复权因子
- 后复权日线 K 线缓存
- 历史筛选结果归档
- 买入清单与部分结算记录

## 4.2 当前最缺的数据

### 4.2.1 分时执行数据

当前最缺的是分时级数据，尤其是尾盘策略需要的：

- 1 分钟或 5 分钟 OHLCV
- 14:30 后分时量价变化
- 14:50 附近可成交价格
- 集合竞价价量信息
- 分时 VWAP

缺少这些数据，会导致尾盘策略只能用日线近似，策略优势无法真正发挥。

### 4.2.2 真实交易约束数据

目前缺少：

- 手续费、印花税、滑点参数
- 涨停买不到、跌停卖不掉约束
- 停牌、复牌、一字板场景
- 成交量占比限制

这会导致回测收益偏乐观。

### 4.2.3 市场环境数据

目前缺少：

- 指数趋势和波动环境
- 行业热度和主线轮动强弱
- 涨停/跌停家数、连板梯队、情绪指标
- 板块拥挤度和风格切换标记

缺少这些数据，会导致策略难以做状态切换，固定参数容易在不同阶段失效。

### 4.2.4 事件与风险数据

目前缺少：

- 财报披露窗口
- 解禁、减持、公告风险
- 龙虎榜、北向、融资融券等资金行为数据
- 停牌、监管函、异动公告等事件数据

这类数据可显著减少“图形好看但事件风险高”的误入选情况。

### 4.2.5 实盘反馈标签

虽然已有买入清单和结算工具，但当前尚未形成完整的策略反馈闭环：

- 实盘买入记录没有系统回流到策略评估
- 实盘偏离信号原因没有结构化记录
- 没有形成“理论信号 vs 实际执行 vs 结算结果”的统一样本

后续建议把这部分沉淀为统一标签表，用于评估策略可执行性偏差。

## 5. 推荐落地顺序

### 第一阶段：先补研究闭环

1. 将 `leader` 纳入统一回测框架
2. 用 `Tushare` 历史数据重跑四类策略，逐日生成历史可买入标的
3. 在回测中落实 `10 万单票预算 + 整百股 + 最多 3 仓 + 跌破 5 日线止损` 等交易规则
4. 统一四类策略的交易明细、资金曲线和统计报表
5. 增加月度收益、回撤、连续亏损、分市场阶段统计

### 第二阶段：补执行口径

1. 引入分时数据，重点服务 `tail`
2. 建立尾盘近似成交价和次日开盘成交价回测口径
3. 增加手续费、滑点、涨跌停成交限制

### 第三阶段：补状态感知与反馈闭环

1. 加入市场状态特征和行业拥挤度特征
2. 做滚动窗口参数验证，不再只看单次历史表现
3. 将实盘买入和结算记录统一回流，形成策略修正依据

## 6. 最终判断

如果只从“可运行”来看，当前体系已经可以持续产出候选。

如果从“是否适合持续优化并逐步接近实盘研究框架”来看：

- `short` 盘后版已经具备主策略雏形，最值得继续迭代
- `rps90` 适合作为简单透明的辅助策略，但需要补质量约束
- `tail` 的关键不是继续手调参数，而是先补分时数据
- `leader` 目前优先级不在调分，而在补回测和明确定位

整体上，当前最大短板不在“模型完全没想法”，而在“回测保真度和数据维度还不够支撑下一阶段优化”。

结合当前新增需求，下一步最优先的工作已经不是继续微调单个策略权重，而是先建立一套可复用的统一历史回测引擎：

- 输入：`Tushare` 历史行情和各策略信号逻辑
- 过程：逐日重算可买标的、按组合约束开平仓、动态维护 `MA5`
- 输出：交易流水、资金曲线、策略对比和可复盘明细
