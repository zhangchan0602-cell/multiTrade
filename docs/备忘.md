# 项目备忘

## 当前重点

- 当前保留两个短线模型：短线多因子-盘后版、短线多因子-尾盘版。
- 中线多因子相关活跃内容已移除，当前前端和本地 API 只面向盘后版与尾盘版。
- 活跃命名统一使用短前缀：盘后版对应 `short_*`，尾盘版对应 `tail_*`。
- 历史快照统一使用短文件名：当前输出 `short_*` / `tail_*`，历史快照 `short_日期时间_*` / `tail_日期时间_*`。

## 启动方式

先设置 Tushare token，再启动本地 API 和前端：

```bash
export TUSHARE_TOKEN=你的token
npm install
npm run api
npm run dev
```

补充说明：

- Python 脚本和本地 API 都依赖 `TUSHARE_TOKEN`。
- 本地 API 默认地址为 `http://127.0.0.1:8787`。
- 前端主要页面：`#/ops`、`#/top20`、`#/myplan`。

## 关键页面

- `#/ops`：操作界面，可执行盘后版和尾盘版脚本，并查看当天 Top5。
- `#/top20`：展示当前 Top5 和历史快照对比。
- `#/myplan`：展示 `myplan.md`。

## 当前脚本入口

- `scripts/tail_screen.py`：短线多因子-尾盘版入口，复用盘后版逻辑。

## Tushare 现状

当前项目已切到 Tushare 获取股票数据，东财接口已从活跃主链移除。

当前 token 已验证可用的接口：

- `daily`
- `adj_factor`
- `bak_daily`
- `stk_factor`

当前 token 不可用或受限较强的接口：

- `trade_cal`：无权限。
- `daily_basic`：无权限。
- `stock_basic`：当前 token 实际上约等于 1 次/小时限制。

## Tushare 抓数实现约定

- 最新行情横截面：优先通过 `bak_daily` 获取。
- 交易日探测：通过 `daily` 获取，避免触发 `bak_daily` 的低频限制。
- 单股 K 线特征：通过 `daily + adj_factor + bak_daily` 组合计算。
- `stock_basic` 超限时：脚本会回退到 `bak_daily` 提供的名称与行业信息继续运行。
- 若未来 `stock_basic` 可稳定调用，可在 `scripts/.cache/stock_basic.csv` 建立或复用缓存，减少频控影响。

## 当前限频注意事项

- `bak_daily` 频率较低，批量测试时不要连续高频手动调用。
- 运行盘后版或尾盘版前，尽量避免同一时间窗口内反复执行大量探测脚本。
- 如果出现频控，优先等待额度恢复，不要继续并发重试。

## 前端与本地 API 约定

- 前端通过 `src/lib/opsApi.js` 请求本地 API。
- 本地 API 服务文件是 `ops_api.mjs`。
- 当前作业键只有两个：`postclose`、`tail`。
- `npm run api` 启动后，操作界面会轮询任务状态和 Top5 数据。

## 维护时优先记住的点

- 若只改盘后版策略，优先检查 `scripts/short_screen.py`。
- 若改共享抓数逻辑，优先检查 `scripts/screen_common.py`，因为盘后版、尾盘版和盈亏更新脚本都会受影响。
- 若改操作界面或本地执行入口，优先检查 `ops_api.mjs`、`src/pages/OpsPage.jsx`、`src/lib/opsApi.js`。
- 若改展示数据，先确认是否应该改当前文件，避免误改 `docs/list/history/` 里的历史快照。
