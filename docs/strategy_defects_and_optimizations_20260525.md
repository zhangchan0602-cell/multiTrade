# 项目各策略缺陷与优化建议

> 日期：2026-05-25
> 结论依据：`scripts/short_screen.py`、`scripts/tail_screen.py`、`scripts/rps90_screen.py`、`scripts/leader_screen.py`、`scripts/strategy_backtest.py`，以及 `docs/list/` 下现有汇总与回测产物。

## 一、先看结论

当前项目里，四个策略不是“都需要微调”，而是处在四种完全不同的问题状态：

| 策略 | 当前可用性判断 | 直接证据 | 核心缺陷 |
|---|---|---|---|
| `short` 盘后多因子 | **最接近可继续迭代** | 最近一次可见汇总为 `1118 -> 32`，现有回测 `70` 笔、胜率 `55.71%`、平均收益 `+4.23%` | 行业拥挤、回测口径与实盘不完全一致、空样本时会退化成另一套策略语义 |
| `tail` 尾盘多因子 | **当前不可直接实盘依赖** | 最近一次可见汇总 `1049 -> 0`，现有回测 `10` 笔、胜率 `20%`、平均收益 `-4.94%` | 盘中策略却大量依赖日线逻辑，且回测允许日线降级，和真实尾盘执行不一致 |
| `rps90` | **更像股票池，不像最终买点策略** | 最近一次可见汇总 `4056 -> 258`，现有回测 `95` 笔、胜率 `37.89%`、平均收益 `-0.59%` | 过于追强，缺少过热、波动、板块拥挤、市场环境过滤 |
| `leader` 龙头抱团 | **有思路，但当前更像宽筛 + 排名** | 最近一次可见汇总 `807 -> 728`，最终通过率高达 `90.2%` | 选择性太弱，行业内分位过于饱和，且缺少独立回测闭环 |

如果只保留一句判断：

- `short` 值得继续做，因为已经出现正收益雏形，但需要先解决口径一致性和拥挤问题。
- `tail` 需要重做，不是简单调阈值。
- `rps90` 适合当“强势股票池”，不适合直接当最终买入榜。
- `leader` 需要先把“筛选”收紧，再谈“排名”。

## 二、分策略分析

## 1. `short` 盘后多因子

### 1.1 当前优点

- 因子结构最完整，已经区分了启动、趋势、活跃、稳定、流动性。
- 现有 `strategy_backtest.csv` 中，`short` 是唯一一个当前仍表现为正期望迹象的策略：`70` 笔、胜率 `55.71%`、平均收益 `+4.23%`。
- 最近一次可见结果中，硬过滤后 `1118` 只，最终 `32` 只，选择性比 `rps90`、`leader` 更合理。

### 1.2 主要缺陷

#### 缺陷 1：回测候选空间和实盘候选空间不一致

实盘默认 `SHORT_KLINE_CANDIDATE_LIMIT` 是 `1200`，而组合回测入口 `strategy_backtest.py` 默认把 `short/tail` 的候选上限强行改成 `80`。

这会带来两个问题：

- 回测挑选的候选集比实盘窄很多，样本分布失真。
- 回测结果不能直接代表线上策略真实表现，尤其对横截面排序模型影响很大。

这不是“小误差”，而是会改变信号来源。

#### 缺陷 2：空样本时会切换成另一套“纯行情策略”

`run_screen()` 在真实 K 线打分结果为空时，会启用 `quote_only_fallback`，直接用纯行情字段重新打分，并把：

- `quote_only_fallback_used = True`
- `pass_momentum_floor = True`
- `pass_next_2_3d_setup = True`

也就是说，空样本时不是“无信号”，而是“换策略继续出信号”。这会导致：

- 线上与线下分析混淆。
- 用户以为拿到的是短线多因子结果，实际拿到的是纯行情降级结果。
- 复盘时很难知道收益究竟来自主策略还是降级策略。

#### 缺陷 3：资金因子仍是代理变量，不是真实资金行为

当前 `money_flow_bias_20` 本质上是“上涨日成交额减去下跌日成交额”的代理量，`price_volume_sync_10` 是价量相关性。它们能描述强弱，但不能回答：

- 是否有主力净流入
- 是否有超大单确认
- 是否只是情绪波动带来的高换手

对于短线策略，这是信息缺口。

#### 缺陷 4：缺少行业拥挤约束

当前最新 `short_top20.csv` 中，化工原料占了 `8/20`。这说明模型虽然做了行业内 z-score，但最终排序没有行业上限，仍然会在某个短期最热赛道内堆叠持仓。

问题不在于“行业集中一定错误”，而在于：

- 组合层面会放大单一主题回撤。
- 一旦主线切换，榜单整体失效。
- 当前项目回测里还没有做行业暴露预算，集中风险会被进一步放大。

#### 缺陷 5：信号目标与出场规则没有完全对齐

策略文档写的是“次日择机买入，持有 2-3 个交易日”，但统一回测仍大量使用通用出场逻辑，例如：

- 涨停即出
- 单日回撤 `5%` 即出
- 跌破 `MA5` 即出

这些规则适合作为组合级风控，但不等于“盘后短线 2-3 天策略”的最佳出场验证口径。

### 1.3 优化建议

1. 先统一 `short` 的实盘与回测候选上限，至少保证回测不再默认缩到 `80`。
2. 把 `quote_only_fallback` 从“可交易结果”降级为“观察名单”，不要和主策略混用。
3. 增加行业上限，例如 Top20 内单行业不超过 `3~4` 只，或组合回测中做行业预算。
4. 引入真实 `moneyflow`、`stk_limit`、`top_list/top_inst`，替换部分成交额代理因子。
5. 为 `short` 单独建立“次日开盘买入 / 次日 VWAP 买入 / 持有 2-3 天”的专项回测，而不是只复用统一出场规则。

### 1.4 优先级判断

`short` 不建议推翻重做，建议作为当前主迭代对象。

## 2. `tail` 尾盘多因子

### 2.1 当前问题比表面更严重

最近一次可见汇总里：

- 硬过滤后样本 `1049`
- 最终符合样本 `0`

现有回测里：

- 仅 `10` 笔交易
- 胜率 `20%`
- 平均收益 `-4.94%`

这说明问题不是“表现一般”，而是**策略定义、数据口径和执行场景三者没有真正对齐**。

### 2.2 主要缺陷

#### 缺陷 1：这是尾盘策略，但核心特征仍然几乎全是日线逻辑

当前尾盘版虽然改了权重和阈值，但底层仍然主要来自：

- 3/5/10/20 日收益
- MA20、MA60
- 20 日量能放大
- 20 日资金偏置
- 20 日最大回撤

这些都是“日线择股因子”，并不是真正的“14:30-14:45 决策因子”。

尾盘交易更需要的是：

- 午后成交量抬升
- 尾盘相对 VWAP 的强弱
- 14:00 后新高突破
- 收盘竞价强弱
- 尾盘回封/抢筹行为

如果没有这些，尾盘版实质上只是“更严格的日线版”，而不是独立策略。

#### 缺陷 2：实盘默认要求盘中快照，但回测默认允许降级成日线

这是当前项目里最需要优先修正的问题之一。

实盘逻辑里，`tail` 默认要求拿到盘中快照，否则会直接中止；但组合回测入口 `_configure_portfolio_env()` 又把：

- `SHORT_TAIL_ALLOW_DAILY_FALLBACK = 1`

强制打开。

结果就是：

- 线上想跑真实尾盘策略，需要盘中数据。
- 回测却可以在没有盘中数据时，退化成日线口径继续跑。

这会直接导致“回测能跑、实盘不能做”，属于策略口径错位，不是普通参数问题。

#### 缺陷 3：过滤条件过严，而且有部分条件互相叠加后几乎堵死样本

尾盘版同时要求：

- 当日必须上涨
- 近 3/5 日必须正动量
- `accel >= 0`
- 必须站上 20 日均线
- `amount_ratio_1_20 >= 1.20`
- `money_flow_bias_20 >= 10%`
- 风险阈值比盘后版更严格

这些条件单看都合理，但叠加在一起后，最新可见结果直接归零。说明当前阈值不是“有点严”，而是已经超出正常信号密度。

#### 缺陷 4：回测成交口径也不符合尾盘交易真实执行

尾盘策略的买点更接近：

- 14:45 附近价格
- 14:50 前后价格
- 收盘竞价成交价格

但当前回测大多仍然使用当日 `close` 或可回退的日线价格，无法体现：

- 尾盘抢筹滑点
- 实盘排队成交问题
- 竞价回落风险

### 2.3 优化建议

1. 把 `tail` 从日线策略中拆出来，明确变成“分钟级因子策略”。
2. 没有盘中快照时，不输出可交易 Top5，只输出观察名单。
3. 新增分钟级特征：`13:30-14:45` 相对量比、尾盘 VWAP 偏离、尾盘新高突破、尾盘回落幅度、竞价强弱。
4. 用“目标每日 5~20 只候选”反推阈值，不要继续用拍脑袋的绝对阈值堆叠。
5. 建立尾盘专属回测：买点用 `14:50` 附近价格，卖点用次日开盘 / 次日午后 / 次日收盘三套方案分别评估。

### 2.4 优先级判断

`tail` 不建议继续小修小补，建议重构。

## 3. `rps90`

### 3.1 当前定位其实已经偏离“最终买入策略”

`rps90` 的核心逻辑非常纯：

- `RPS20 >= 90`
- `RPS90 >= 90`
- 再加一点成交额百分位 bonus

这会天然选出“最近涨得最多的股票”，但并不能保证：

- 位置不过热
- 波动可以承受
- 板块没有拥挤到末端
- 买入时点合适

所以 `rps90` 更像“强势股票池”，而不是“最终买点策略”。

### 3.2 主要缺陷

#### 缺陷 1：过于依赖收益率排序，几乎就是追强

当前综合分：

```text
0.40 * RPS20 + 0.60 * RPS90 + amount_bonus
```

本质上仍然是“谁涨得多谁靠前”。缺的不是再加一个小权重，而是缺少第二层结构化过滤：

- 离均线是否过远
- 波动是否过大
- 最近是否连续加速到过热
- 板块是否已经拥挤
- 市场是否处于趋势延续环境

#### 缺陷 2：板块拥挤明显

当前 `rps90_top20.csv` 中：

- 半导体 `6` 只
- 元器件 `4` 只

前 `20` 只里就有 `10` 只集中在两个高弹性方向。

这类集中在强趋势行情里会很好看，但一旦板块轮动，回撤会很陡。

#### 缺陷 3：现有回测已经给出负期望警告

`strategy_backtest.csv` 里 `rps90` 的统计结果：

- `95` 笔
- 胜率 `37.89%`
- 平均收益 `-0.59%`
- 出场原因里 `stop_loss` 和 `retracement` 合计占绝大多数

这说明当前策略抓到了强者，但买入时点偏后，追高回撤明显。

#### 缺陷 4：没有市场环境开关

RPS 策略通常只在趋势扩散阶段更有效。在震荡市、切换市、退潮市里，最高 RPS 往往是最拥挤的尾部仓位。

当前项目没有给 `rps90` 加任何市场环境过滤，例如：

- 指数是否在 MA20/MA60 之上
- 市场涨跌家数扩散度
- 高位股跌停率 / 炸板率
- 主线板块强度

### 3.3 优化建议

1. 把 `rps90` 从“直接买入榜”改成“强势股票池”，再叠加第二层择时。
2. 增加过热过滤，例如：离 `MA20` 偏离过大不买、20 日波动率过大不买、连续大涨后不追。
3. 增加行业上限，至少避免 Top20 被单一主线吞没。
4. 增加市场环境开关，只在趋势扩散阶段输出最终信号。
5. 把 `RPS20/RPS90` 与趋势质量、换手结构、回撤约束结合，形成“强而不太热”的版本。

### 3.4 优先级判断

`rps90` 不建议废弃，但建议降级为上游股票池。

## 4. `leader` 龙头抱团

### 4.1 当前最大问题不是打分，而是筛选太宽

最新可见结果：

- 全宇宙 `4553`
- 硬过滤后 `807`
- 最终通过 `728`

也就是硬过滤后的股票里，约 `90.2%` 最终都被保留。说明当前模型更像：

- 先宽筛出一批“像龙头”的股票
- 再做排序

但它还没有形成真正严格的“龙头抱团信号”。

### 4.2 主要缺陷

#### 缺陷 1：行业内百分位门槛过宽，且容易在小行业里饱和

当前核心硬条件之一是：

- 行业内 `20/60` 日涨幅百分位都 >= `70`

这在大行业里还算有区分度，但在股票数较少的行业里，很容易出现：

- 只要行业整体在涨，很多股票都能过线
- 排名值很快接近 `100`
- 失去真正的“龙头稀缺性”

从当前 `leader_top20.csv` 看，很多标的 `sector_rank_20`、`sector_rank_60` 都接近甚至等于 `100`，有明显饱和现象。

#### 缺陷 2：最终通过率过高，说明后续分数更像排序器而不是筛选器

龙头抱团策略理论上应该是中期强者中的少数优质样本，而不是大量股票都能进入“通过名单”。

当 `807 -> 728` 时，当前 `leadership/trend/cluster/stability` 分数更多是在做相对排名，而不是在做强筛选。

#### 缺陷 3：无 K 线时的降级逻辑会改变策略含义

如果没有有效 K 线，当前逻辑会退化成：

- 用行业领先度 + 成交额打分
- `trend_score/cluster_score/stability_score` 近乎失效

这相当于把“龙头抱团策略”退化成“行业强势 + 大成交额策略”，语义变化很大。

#### 缺陷 4：缺少独立回测闭环

虽然 `strategy_backtest.py` 已经支持 `leader`，但当前 `docs/list/` 下并没有看到对应的独立历史回测产物，说明：

- 功能代码已接上
- 策略验证文档还没有闭环

没有性能闭环，就无法判断 `leader` 的真实收益、回撤、持有期是否匹配当前设计。

#### 缺陷 5：组合回测再次缩小了候选空间

`leader` 实盘默认 `KLINE_CANDIDATE_LIMIT = 4000`，但组合回测默认只给 `300`。这会让回测与实盘结果再一次脱节。

### 4.3 优化建议

1. 先把 `leader` 的目标从“宽筛 + 排名”改成“强筛 + 排名”。
2. 增加最低分地板，例如 `trend_score`、`cluster_score`、`stability_score` 必须同时为正，或必须高于某个分位。
3. 对行业样本数过小的行业做额外约束，避免分位排名失真。
4. 引入真实资金确认，如 `moneyflow`、`hk_hold`、`top_inst`，让“抱团”不再只靠价量代理。
5. 先补做 `leader` 的独立历史回测文档，再决定是否扩大实盘权重。

### 4.4 优先级判断

`leader` 的方向可保留，但在没有回测闭环前，不建议作为核心资金分配策略。

## 三、跨策略共性缺陷

## 1. 实盘口径和回测口径不一致

这是当前项目最需要先修的系统性问题。

典型表现：

- `tail` 实盘默认要求盘中快照，但回测默认允许日线降级。
- `short/tail` 实盘默认候选 `1200`，组合回测默认候选 `80`。
- `leader` 实盘默认候选 `4000`，组合回测默认候选 `300`。
- 多个策略最终都被统一压进同一套组合级出场规则里。

如果口径不一致，再精细的参数优化也会失真。

## 2. 多个策略仍依赖同一批日线因子，差异不够本质

当前 `short`、`tail`、`leader` 虽然名字不同，但底层都大量依赖：

- 日线收益率
- 均线偏离
- 成交额放大
- 波动和回撤

问题在于：

- `tail` 本应依赖分钟级行为
- `leader` 本应依赖中期机构资金确认
- `short` 本应依赖短期启动质量

现在三者的差异更多是权重差异，而不是信息层差异。

## 3. 真实资金、板块热度、事件风险没有接进来

当前主要还是量价横截面模型，缺少：

- 真实资金流向
- 板块热度和扩散度
- 涨停生态标签
- 龙虎榜席位确认
- 业绩/减持/质押等风险事件

这会导致模型能识别“谁在涨”，但还不能识别“为什么涨、还能不能追、有没有风险”。

## 4. 回退机制太像“换策略”，不是“降级展示”

无论 `short` 的 `quote_only_fallback`，还是 `leader` 的无 K 线降级，本质问题都一样：

- 主策略条件失效时，没有明确告诉用户“当前不可交易”。
- 而是继续产出另一套语义不同的结果。

这会削弱策略边界。

## 5. 缺少滚动验证和参数稳定性检查

当前能看到很多静态阈值和手工权重，但仓库里还没有体现出完整的：

- walk-forward 验证
- 参数扰动稳定性检查
- 不同市场阶段分桶统计
- 不同行业环境分桶统计

这意味着当前参数很可能“在看过的数据上合理”，但还没有证明它们在未来也稳。

## 6. 数据工程层面还有基础风险

虽然这不只属于策略，但会直接影响策略可信度：

- `screen_common.py` 中存在硬编码 Tushare Token 风险。
- 多处缓存会让回测和实时调用共享数据路径，需要防止脏缓存影响判断。
- 当前文档与回测产物并不总是同一交易日生成，横向比较要谨慎。

## 四、优化优先级建议

## P0：先修“口径一致性”，否则优化会失真

1. 统一实盘与回测的候选空间上限。
2. `tail` 官方回测禁止日线降级，拿不到盘中数据就记为不可交易。
